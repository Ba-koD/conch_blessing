The [provider implementation](https://github.com/TeamREPENTOGON/REPENTOGON/blob/main/repentogon/LuaInterfaces/Entities/LuaEntityPickup.cpp) appends to a maximum of eight queued entries and returns a boolean. Installed Golden Items 1.1 (Workshop 3338495603) exposes `HasGoldenItem(id)`, `SetGoldenItem(id, player)` and `ExaustGoldenItem(id)` in `scripts/tools/util_golden_item.lua` (lines 24–49); its active ledger is global by item ID. `main.lua` lines 149–155 reject active `TurnItemGold`, so natural golden-active acquisition is not supported by this fork. Production queries the held Severed Oath's golden state through the guarded public API, preferring the player/slot-aware provider. Pedestal goldenization never controls +1/+2. Tests explicitly set/exhaust and restore the held active's state through public APIs; they do not claim natural acquisition or edit the providers.

Sealed Demon Sword persistence (checked 2026-10-09): [EntityNPC:TrySplit](https://repentogon.com/EntityNPC.html#trysplit) takes `(DefaultDamage, Source, DoScreenEffects)`; its boolean does not identify newly split children. [MC_PRE_NPC_SPLIT](https://repentogon.com/enums/ModCallbacks.html#mc_pre_npc_split) runs before the split decision and is not a result notification. No documented already-split getter was found. Native per-room state uses `SaveManager.GetRoomSave(nil, false, descriptor.ListIndex)`; StageAPI extra rooms use `GetCurrentRoom().PersistentData`, which installed StageAPI includes in `LevelRoom.SavedFields`. Record processed InitSeed/type identity and retain the room's health baseline/budget across re-entry. The health heuristic can still misclassify naturally weaker same-kind enemies and is not proof of exact child ownership.

## Basic Rules

- Kronos room-effect cleanup uses [`ModReference:AddPriorityCallback`](https://wofsauge.github.io/IsaacDocs/rep/ModReference.html#add-priority-callback) with [`CallbackPriority.EARLY`](https://wofsauge.github.io/IsaacDocs/rep/enums/CallbackPriority.html) for `MC_PRE_GAME_EXIT`. Installed StatsAPI (`statsapi_3679589576/scripts/statsapi_core.lua`) serializes and writes its run data at default exit priority; `unifiedMultipliers:SaveToSaveManager` alone updates its memory, not disk. Clear transient contributions before that write, retain a guarded default-priority fallback, and reconcile on game start/player update regardless of registration order. This is source-level evidence; real quit/Continue still requires in-game verification.

- In-game test fixtures: [`Entity:TakeDamage` / `HitPoints`](https://wofsauge.github.io/IsaacDocs/rep/Entity.html#takedamage) use deferred HP updates; observe settled HP on later normal updates before comparing damage. [`Room:SpawnClearAward`](https://wofsauge.github.io/IsaacDocs/rep/Room.html#spawnclearaward) exercises the engine award operation but alone does not prove a natural enemy-death room clear. Keep a real-death case as well, and distinguish callback-generated pickups from the engine's subsequent vanilla award. Test-only observers must load after ItemData callback registration to take that boundary snapshot.

- Use the `/rep/` docs first for the current Repentance+ base API. Search engines often return `/abp/` or `oldDocs`; those are legacy references unless the task explicitly targets old behavior.
- This repository does not currently pin a minimum Repentance/Repentance+ executable. A method in `/rep/` is not proof that it exists on older supported builds, and a method in editor stubs is not proof that it is base-game API. Check the intended runtime and keep capability guards where the baseline is not guaranteed.
- Until a minimum build is pinned, a new API choice must either declare and test its target build or provide a capability-checked fallback. If neither is possible, resolve the support/dependency policy before writing the feature.
- Use `repentogon.com` for REPENTOGON-only classes, callbacks, and method extensions. Use the installed provider's versioned documentation/source for StatsAPI, Magic Conch, MCM, EID, StageAPI, MiniMAPI, GoodTrip, and other mod APIs.
- For behavior questions, read in this order: class/function page, related enum page, related XML page, then tutorial or FAQ page.
- For callbacks, always read the callback signature, optional parameter matching, and return-value behavior before returning anything from a callback.
- For XML, read the exact file page before choosing `content` or `resources`; add/merge/replace/no-effect behavior differs by XML file.
- For item content, remember the local source of truth: item metadata starts in `scripts/conch_blessing_items.lua` and its player-facing text in `scripts/locale/<lang>.lua`, then `generate_xml.py` may regenerate `content/items.xml` and `content/itempools.xml`.
- For custom entities, remember the current local limitation: `generate_xml.py` owns all of `content/entities2.xml` but emits familiar entries only. It is not safe to add a manual monster entry until the source/generator workflow is extended.
- The docs are community-maintained. If documented behavior differs from a reproducible test on the intended target build, trust that runtime result for that build. Record durable project-wide conclusions in `AGENTS.md` or this reference map, keep only narrow implementation quirks near the affected code, and do not generalize one installed build's result to an unpinned compatibility baseline.

## Appraisal Backends And Saved Formats

- New version-11 `appraisal_trinkets_death_certificate` sessions use `native_gallery_manager.lua` and `death_certificate_gallery_rooms.lua`. Invoke [EntityPlayer:UseActiveItem](https://wofsauge.github.io/IsaacDocs/rep/EntityPlayer.html#use-active-item) with the real Death Certificate, adopt its native dimension-2 HOME descriptor set after entrance arrival, and inspect [RoomConfigRoom.Spawns](https://wofsauge.github.io/IsaacDocs/rep/RoomConfig_Room.html#spawns) / [RoomConfigSpawn](https://wofsauge.github.io/IsaacDocs/rep/RoomConfig_Spawn.html). Extracted `35.home.stb` identifies the entrance with subtype 33 and stock rooms with subtype 34; stock coordinates are zero-based interior positions, so runtime grid positions include the one-cell wall border. Do not call RoomConfig.AddRooms or Level.TryPlaceRoom, rewrite descriptors, or replace vanilla layouts. Remove collectible pedestals during the active visit and replace them with the complete frozen trinket catalog at the vanilla positions. Canonical DC owns the private return snapshot; later movement/return uses the dimension-aware five-argument Game:StartRoomTransition. Persist only native descriptor fingerprints, pedestal coordinates, and exact catalog/source seeds.
- Continued version-9 sessions remain on the old StageAPI backend until floor settlement. Every reference below to Appraisal's fixed negative map, empty-shell restoration, MiniMAPI virtual graph, tagged DC detour, or independence from dimension 2 applies only to that compatibility backend. It does not describe new version-11 sessions. The dispatcher never converts a saved virtual graph into native descriptors or builds a new virtual graph.
- Under [REPENTOGON MC_PRE_USE_ITEM](https://repentogon.com/enums/ModCallbacks.html#mc_pre_use_item), `{Discharge=false}` cancels activation before accepted-use counters. Base `true` suppresses the default effect but may still discharge. Appraisal validates and journals in PRE_USE, cancels rejected starts there, and confirms the prepared visit in the actual USE callback. Its next semantic update issues canonical DC once after the outer use unwinds. Ordinary DC is suppressed only during an active Appraisal visit; completed visits do not cancel it. The manager's exact canonical entry call remains allowed.

## Quick Lookup

Test observers: [Isaac.FindByType](https://wofsauge.github.io/IsaacDocs/rep/Isaac.html#findbytype) excludes `FLAG_NO_QUERY`; use `GetRoomEntities` for complete familiar presence checks and still verify ownership/liveness. [MC_POST_NPC_DEATH](https://wofsauge.github.io/IsaacDocs/rep/enums/ModCallbacks.html#mc_post_npc_death) reports death-animation completion, while `MC_POST_ENTITY_KILL` precedes the animation and `MC_POST_ENTITY_REMOVE` also includes room unloads. Keep these events distinct in test evidence; removal alone is not a kill.

Choose `noHourglass` deliberately. Use `GetTempSave` only for state that should be discarded on leaving the room.
- New custom entity or monster: do not put it in ItemData or hand-edit the generated `content/entities2.xml`. First add a dedicated entity metadata source and extend/replace the generator workflow, then wire an explicit entity loader into core. Cache `Isaac.GetEntityTypeByName` and `Isaac.GetEntityVariantByName`; failed lookup returns `0` and `-1` respectively, and there is no subtype-by-name API.

## Search Tips

- Start with docs search or a web query like `site:wofsauge.github.io/IsaacDocs/rep EntityPlayer AddCacheFlags`.
- For an API that might be REPENTOGON-only, search both `site:wofsauge.github.io/IsaacDocs/rep MethodName` and `site:repentogon.com MethodName`; then check the intended minimum runtime rather than trusting autocomplete.
- On large class pages, use browser search for the exact API name, for example `GetCollectibleNum`. The visible table of contents may split method words with dots, but the real API name is still the plain Lua method name.
- If a function signature links to enum types, open those enum pages immediately. Enum details often explain names used in XML or flags used by callbacks.
- If a page has `Bugs`, `Notes`, or `Version Difference` sections, treat those as part of the API contract for this mod.
- If a callback has optional entity-type or variant filtering, use it instead of checking every entity inside a broad callback.

## Common Cautions

- `/rep/` is the current Repentance+ documentation, not an archived minimum-Repentance contract. Keep fallbacks for older builds until the project explicitly drops them.
- `Isaac.GetFrameCount()` and `Game():GetFrameCount()` are not interchangeable. Check the relevant page before using frame counts for timers.
- `Isaac.GetRoomEntities()` and `Isaac.FindByType()` are useful, but avoid repeated scans inside broad update callbacks unless the result is cached or the entity set is small.
- `MC_LEVEL_GENERATOR` exists in the enum and local callback mapping but is documented as inactive; never use it as a custom-floor hook.
- `MC_POST_ENTITY_KILL`, `MC_POST_NPC_DEATH`, and `MC_POST_ENTITY_REMOVE` are different lifecycle events. Removal can occur during room unload or run shutdown and is not proof of a death.
- `MC_PRE_ROOM_ENTITY_SPAWN` can replace layout spawn entries; it is not a room registration or room placement API.
- Entity `Type`, `Variant`, and `SubType`, room type/variant/subtype, `LevelStage`, `StageType`, STB stage IDs, and entity `bossID` are separate identifier domains. Do not reuse or compare them without checking the relevant docs.
- Native grid entities can be spawned and modified, but adding a brand-new grid-entity type requires an explicitly adopted extender/framework mechanism or a normal entity/effect emulation.
- `content/entities2.xml` is currently generator-owned and familiar-only. A manual monster or boss entry will be lost on the next generator or pre-push run.
- XML/ANM2/STB/sound/spritesheet changes require a full game restart; `luamod` only proves Lua reload behavior.
- The cosmetic morph renderer uses [Sprite](https://wofsauge.github.io/IsaacDocs/rep/Sprite.html) instances (`Load`, `ReplaceSpritesheet` then `LoadGraphics`, `SetFrame`, `Render`), never vanilla effect entities. Its optional flooded-floor overlay draws in REPENTOGON's [MC_PRE_BACKDROP_RENDER_WATER](https://repentogon.com/enums/ModCallbacks.html#mc_pre_backdrop_render_water), gated by callback availability. This is the per-frame render hook; `MC_POST_BACKDROP_PRE_RENDER_WALLS` is texture preparation and cannot advance an overlay. Without the render hook only rain/ripples render. Familiar snapshots prefer capability-checked [Sprite:Copy](https://repentogon.com/Sprite.html#copy) to preserve replacement sheets; the base fallback loads the original ANM2 and its current base/overlay pose, without mutating a live familiar. The storm lead-in uses low-pitched `SOUND_THUNDER` (472); its strike uses distinct `SOUND_LIGHTBOLT` (172) at normal pitch, verified against the documented enum and extracted `sounds.xml` (`V2/light_bolt_02/03/04.wav`). The HTML preview embeds `light_bolt_02.wav` for that strike. Never substitute the electronic `SOUND_REDLIGHTNING_ZAP*` samples. Default template cues are also one-shots: cancellation/completion must not call shared-ID `SFXManager:Stop` or `AdjustVolume` on unrelated playback. Its darkness/flash are scene-owned Sprite overlays, without `Game:Darken`, curse changes or persisted room color. The storm uses a generator-owned soft alpha aperture centred on the item plus clipped, non-overlapping edge fills; darkness ends on the strike frame. Installed Astro Items references differ: `prometheus.lua`/`curse.lua` apply `CURSE_OF_DARKNESS`, while `book-of-moon.lua` sets `RoomDescriptor.FLAG_PITCH_BLACK` and spawns a gameplay moonlight. Those persistent gameplay operations are references for appearance, not part of cosmetic morphs. Candle ignition/burst uses `SOUND_CANDLE_LIGHT` / `SOUND_FLAME_BURST`, and the rocket uses `SOUND_ROCKET_LAUNCH` from the [SoundEffect enum](https://wofsauge.github.io/IsaacDocs/rep/enums/SoundEffect.html). The viewer spawns an explicit origin [EntityPickup](https://wofsauge.github.io/IsaacDocs/rep/EntityPickup.html) and calls the shared targeted upgrade queue; `Morph` and titles remain owned by the normal transaction. Its developer-only real-pickup mode requires [MC_PRE_CHANGE_ROOM](https://repentogon.com/enums/ModCallbacks.html#mc_pre_change_room) (installed `enums_ex.lua`: 1061) to remove its exact fixture before room persistence; `MC_POST_NEW_ROOM` alone is too late. `MC_IS_PERSISTENT_ROOM_ENTITY` receives only type/variant and cannot distinguish one preview pickup, so never suppress all collectibles/trinkets through that callback. The viewer reads [Input.IsButtonTriggered](https://wofsauge.github.io/IsaacDocs/rep/Input.html#isbuttontriggered) from `MC_POST_RENDER`, advances animation time only from `MC_POST_UPDATE`, and intercepts `ACTION_RESTART` and directional actions through `MC_INPUT_ACTION` while open (`false` for pressed/triggered hooks, `0` for value). Its optional LanaPixel [Font](https://wofsauge.github.io/IsaacDocs/rep/Font.html) uses UTF-8 drawing; builds without that font get English labels through `Isaac.RenderText`.
- `items_metadata.xml` is usually not needed for this mod; quality and tags should generally live in `items.xml` data generated from `ConchBlessing.ItemData`.
- `itempools.xml` documentation is thin. For pool edits, compare against existing generated `content/itempools.xml`, the `ItemPoolType` enum, and in-game behavior.
- Search results can mix Repentance+, AB+, and old docs. Verify the URL contains `/rep/` before relying on a page.

- Morph snapshots use base [Color.Lerp](https://wofsauge.github.io/IsaacDocs/rep/Color.html#lerp) with the same color at both endpoints to detach all tint, colorize and offset values. Borrowed `Sprite.Color`/`Sprite.Scale` values must not serve as restoration snapshots across assignments; copy vectors numerically as well. Offline property doubles exercise stable mutable backing storage instead of assuming Lua table replacement.

- Wardrobe integration: installed Old Wardrobe 1.16 (`../old wardrobe_2488945061/main.lua:823`) scans `GetCollectibles().Size - 1`, including modded item IDs, and lists held configs with `Costume.ID > 0`. Its ordinary item tab toggles `EntityPlayer:AddCostume(config,false)` / `RemoveCostume(config)`; it exposes no read API for its private disabled list. Old Wardrobe + 1.5 adds a separate null-costume catalog via `OWRP.AddNewCostume`, which is unnecessary for an item-linked costume. Bind the generated local item ID/type through [costumes2.xml](https://wofsauge.github.io/IsaacDocs/rep/tutorials/AddingCostumesWithoutLUA.html). The engine attaches passive costumes after pickup animation and removes them on item loss. Hemispatial Neglect uses a fully transparent textured `extra` layer with priority -1 (negative priority is also present in extracted vanilla costumes) and checks [GetCostumeSpriteDescs](https://repentogon.com/EntityPlayer.html#getcostumespritedescs) / [CostumeSpriteDesc:GetItemConfig](https://repentogon.com/CostumeSpriteDesc.html#getitemconfig) for its exact ID AND item type; no visible-layer test, costume insertion loop or wardrobe patch. The 2026-10-11 runtime log confirms that a layerless control costume raises `no layers` when equipped and subsequently crashes inside native `RemoveCostume` from Old Wardrobe. That design is prohibited; generator validation now requires texture/layer/animation links. The replacement still needs an in-game wardrobe toggle check.


- Hemispatial Neglect appearance uses guarded [MC_PRE_PLAYER_RENDER](https://repentogon.com/enums/ModCallbacks.html#mc_pre_player_render), [Entity:Render(offset)](https://wofsauge.github.io/IsaacDocs/rep/Entity.html#render), and [Renderer.CreateImage / RenderToImage](https://repentogon.com/renderer/Renderer.html) with [Image:Render](https://repentogon.com/renderer/Image.html), SourceQuad/DestinationQuad bounds. The current public `LuaRender.cpp` restores the previous render target even after a Lua callback error; the mod additionally restores its re-entry guard and returns nil on failure. Full-viewport captures retain native coordinates, water clip planes and draw offsets; no `Visible`, live sprite, shader or costume fields are overwritten. The cosmetic follows head direction: front hides screen-left, rear hides screen-right, left profile retains the native draw, and right profile keeps only the alpha silhouette boundary. The right profile uses `Image:RenderWithShader`, `Renderer.LoadShader`, and the documented `Renderer.VertexAttributeFormat` POSITION/COLOR/TEX_COORD/VEC2 descriptor (not GLSLType enums); its one-texel sampling step uses the padded image dimensions. Missing outline-only APIs fall back to a black silhouette with an observable diagnostic. The shader discards pixels outside the outline rather than emitting tinted RGB with zero alpha across the full-viewport quad. Offscreen WebGL 1/2 tests compile it and check outline/alpha pixels plus unchanged background RGBA under straight-alpha, premultiplied and additive blending after repeated draws; these do not validate the Isaac renderer integration. This is not a reconstructed 3D anatomical mask; held art within the native player draw shares the clip, and the separately rendered native shadow is retained. Rendering/alpha/costume/water/reflection correctness still requires an in-game check. Capability checks are required even with REPENTOGON installed; no minimum version is inferred from documentation or DLL strings.
- [REPENTOGON EntityPlayer](https://repentogon.com/EntityPlayer.html#setteardisplacement) exposes `GetTearDisplacement` / `SetTearDisplacement`: 1 is right, -1 is left; native fire normally flips the previous value first. [Lua binding source](https://github.com/TeamREPENTOGON/REPENTOGON/blob/main/repentogon/LuaInterfaces/Entities/LuaEntityPlayer.cpp) writes `_tearDisplacement` directly. No eye-enabled mask or per-eye fire-delay setter was found in this public binding or its EntityPlayer/Weapon documentation. This is a finding about the exposed Lua surface, not a claim that the engine lacks eye-specific behavior (Eye Drops is an in-game control case).
- The displacement override was rejected and removed. The accepted prototype now restricts ordinary `WEAPON_TEARS` only: `MC_EVALUATE_TEAR_HIT_PARAMS` marks right-eye (`TearDisplacement == 1`) results with the engine-allocated `NEGLECT_TEAR` variant from `scripts/entities/definitions.lua`, clears damage/flags, and hides them. Tear init mutes the marked entity without interrupting construction; post-fire or pre-update removes it without a death/impact event. Split children inherit a namespaced marker. Other weapon types and familiar sources are deliberately untouched. This is post-spawn suppression, not a native pre-fire veto; real engine coverage is pending.
- [MC_EVALUATE_TEAR_HIT_PARAMS](https://repentogon.com/enums/ModCallbacks.html#mc_evaluate_tear_hit_params) passes WeaponType and TearDisplacement but only mutates TearParams; it has no cancellation return. [MC_PRE_ENTITY_SPAWN](https://wofsauge.github.io/IsaacDocs/rep/enums/ModCallbacks.html#mc_pre_entity_spawn) permits type/variant/subtype/seed substitution, not cancellation; false or type zero is unsafe. [MC_POST_TRIGGER_WEAPON_FIRED](https://repentogon.com/enums/ModCallbacks.html#mc_post_trigger_weapon_fired) is after firing and cannot cancel. Per-weapon fire callbacks are also post-fire; Bone Club runs only at initial creation, not each swing. The exposed [Weapon](https://repentogon.com/Weapon.html) interface has shared fire-delay/charge controls, no eye enable mask. [MultiShotParams](https://repentogon.com/MultiShotParams.html) exposes an eye count rather than a left/right mask; changing it cannot be claimed to cancel one eye across all weapon types. No unified pre-fire left-eye veto was found in the official documentation and public Lua binding/source inspected on this date.
- Any future fallback must establish exact per-attack eye provenance for tears, lasers, knives, bombs and secondary attacks; do not infer it from screen X, travel direction, or a player's later alternating-eye value. Zero damage, post-spawn removal, overriding every attack to the right, and a shared 50% tears multiplier are distinct behaviors and do not satisfy a true pre-fire eye veto.
- A practical suppression experiment is distinct from native cancellation: mutate the selected eye’s `TearParams.TearDamage`/`TearFlags` where the engine supplies that eye, then suppress rendering, collision and updates of an exactly identified attack before removing it. The [base TearParams fields](https://wofsauge.github.io/IsaacDocs/rep/TearParams.html), REPENTOGON pre-update/collision hooks, and tear/laser `SetInitSound(SOUND_NULL)` supply pieces of this approach; they do not establish complete weapon coverage or suppress effects that already ran inside the fire function. Damage zero alone is insufficient. Preserve native firing cadence/charging and test both emitted attacks and secondary effects against independent controls before enabling a weapon path.
- Additional public-source evidence: `CustomCallbacks.cpp` calls `super(...)` before each `MC_POST_FIRE_*` callback. Native `Entity_Player::FireTechLaser` receives a `leftEye` boolean, but the Lua `MC_POST_FIRE_TECH_LASER` callback forwards only the resulting laser. `GetTearHitParams` forwards both `tearDisplacement` and `source`, but that is not a documented one-to-one relationship with a newly spawned entity; callers may query params without firing. Never associate the next spawn with the last params query by frame or queue order. Exposing native origin and a cancellable firing boundary in REPENTOGON remains the robust route for guaranteed coverage.
